# NUVA v4.4 — Full source audit

Date: 2026-08-29 (Asia/Dhaka)

## Verdict

The runnable backend suites and all repository-level Android preflights pass after two build hygiene
fixes. A complete Android APK/resource build and physical-device run are still not verified because
this sandbox cannot download Android/Gradle artifacts from Google/Maven/Gradle CDNs and its GitHub App
cannot dispatch the existing APK workflow.

It is therefore accurate to say **source preflight passed**, but not accurate to say the APK is fully
device-verified. The hardened Android build is version **4.4.1** (`versionCode 29`).

## Problems found and fixed

### 1. Fresh-clone Gradle bootstrap was broken

`./gradlew` initially failed with:

```text
Could not find or load main class org.gradle.wrapper.GradleWrapperMain
```

The repository ignored/omitted `android/gradle/wrapper/gradle-wrapper.jar`. The exact wrapper JAR from
the official Gradle `v8.9.0` tag is now committed.

```text
SHA-256 498495120a03b9a6ab5d155f5de3c8f0d986a449153702fb80fc80e134484f17
```

`android_contract_check.py` now requires the file, checksum and `gradle-8.9-bin.zip` wrapper version.
On a normal network, a fresh clone can bootstrap without an already-installed Gradle.

### 2. Dev/test dependency audit reported 10 vulnerabilities

Before the fix:

- production dependencies: **0 vulnerabilities**;
- all dependencies: **5 moderate, 4 high, 1 critical**;
- vulnerable graph came from dev-only `@vercel/node` and Vitest 2/Vite 5 tooling.

Fix:

- replaced the full `@vercel/node` dev graph with the small local structural interfaces in
  `backend/types/vercel.ts`;
- upgraded Vitest to `4.1.11`;
- reran strict TypeScript and every test.

After the fix:

```text
npm audit: 0 total vulnerabilities
```

No production runtime dependency or API response contract changed.

## Additional runtime/security bugs fixed

- Replaced unmanaged Home/History/Memory/Settings/Onboarding coroutines with `viewModelScope` or
  composition-owned scopes; Room `stateIn` collectors now stop when unsubscribed.
- `VoiceController` now owns a `SupervisorJob`, cancels its complete scope on destruction and reads
  language/TTS preferences asynchronously instead of blocking the main thread on DataStore.
- TTS no longer drops the first reply while Android initializes the engine; only the latest pending
  reply is retained, and Settings shuts its test engine down with the ViewModel.
- Settings password input is masked and cleared immediately after submit.
- Custom backend/Supabase URLs are HTTPS-only and reject embedded credentials, query/fragment
  tokens, invalid ports and parent-path traversal.
- The stale duplicate AI fallback hostname now uses the single production endpoint constant.
- Supabase access/refresh JWTs are AES-GCM encrypted with Android Keystore; legacy plaintext,
  undecryptable and stale refresh-token values fail closed and are cleared. Backend/Supabase config
  changes also clear the old session before it can reach a new origin.
- Wake microphone and scheduled-draft restore moved out of `Application.onCreate`, so boot/background
  process creation cannot start a mic or race the BootReceiver. The receiver performs one boot/update
  restore; a visible Activity performs one force-stop recovery restore.
- Financial notification packages are rejected before `Notification.extras` is touched, so their
  title/text never enters NUVA's transient notification store; initial refresh is capped to 30 items.
- Calendar event locations now pass the same credential/code redaction boundary as titles.
- Home Assistant endpoint changes require a freshly supplied token and failed validation cannot
  partially save the new URL.
- Torch state callback registration is now one-time per process instead of leaking a callback on
  every toggle.

## Full Gradle attempt

The official wrapper now launches correctly and attempts to download Gradle 8.9. The sandbox network
terminates TLS to `services.gradle.org`, so the distribution cannot be fetched here.

For additional diagnosis, a temporary full JDK 17 and a locally available Gradle installation were
used. Gradle progressed through settings and project loading, then stopped while resolving
`com.android.application:8.7.3`; TLS connections to `dl.google.com`, Maven Central and the Gradle
Plugin Portal are terminated by the sandbox network. This is an environment/artifact-availability
blocker, not a Kotlin error reported by the build.

The temporary diagnostic Gradle version was not used to claim application compatibility. The project
continues to pin the required Gradle 8.9/AGP 8.7.3 pair.
