# NUVA v4.2 — APK build and real-device QA status

Date: 2026-08-28

## Current result

**Source/API readiness improved; a complete APK has not yet been produced in this sandbox.**

The sandbox originally had no Java runtime, Android SDK or Gradle installation. A temporary Java 17
runtime was successfully bootstrapped through `jdk4py`, a public Android 35 API jar was retrieved from
an AOSP Git mirror, and the Kotlin JVM compiler distribution was obtained through npm. This enabled
real Kotlin semantic/API compilation of the highest-risk v4.0–v4.2 modules instead of syntax parsing
alone.

Full `:app:testDebugUnitTest`, lint and `:app:assembleDebug` remain blocked because this environment
cannot reach the Gradle/Google Android SDK and Maven artifact CDNs. GitHub Actions cannot be manually
dispatched by the Arena GitHub App (HTTP 403), and the same app is not allowed to modify workflow
files. No APK or device-tested claim is made.

## New deterministic tooling

### Always available

```bash
cd android
python3 tools/parser_mirror_check.py
python3 tools/android_contract_check.py
```

`android_contract_check.py` verifies:

- Android version and API-client version stay synchronized;
- all manifest components resolve to Kotlin implementations;
- VoiceInteractionService/session/recognition metadata stays complete;
- microphone services remain non-exported foreground services;
- Android 11+ recognition package visibility remains declared;
- no system hotword, broad storage, SMS-read, contact-write or calendar-write permission appears;
- AssistStructure/screenshots remain disabled;
- recognition self-recursion and Android 12+ caller attribution guards remain present;
- screen-off pause, wake timeout and self-TTS rejection remain present;
- Home Assistant and Calendar provider intents remain unreachable from server/AI wire payloads.

### Focused Android API compile

When Java 17, a Kotlin compiler distribution and Android 35 `android.jar` are available:

```bash
cd android
python3 tools/focused_android_api_compile_check.py \
  --kotlinc /path/to/kotlinc-jvm \
  --android-jar /path/to/platforms/android-35/android.jar
```

## Required full-build commands

Run these on Android Studio or a machine with JDK 17, Android SDK 35 and Gradle 8.9:

```bash
cd android
gradle --no-daemon :app:testDebugUnitTest
gradle --no-daemon :app:lintDebug
gradle --no-daemon :app:assembleDebug
sha256sum app/build/outputs/apk/debug/app-debug.apk
```

Do not distribute an APK until all three commands pass.

## Real-device test matrix

Record device model, Android version, OEM skin, app version and evidence for every row.

### Install and baseline

1. Fresh install v4.2.0 (`versionCode 26`) and complete onboarding.
2. Deny every optional permission once; verify typed/offline commands still work.
3. Grant each permission from its documented prompt; verify no permission is silently enabled.
4. Reinstall/update the APK; check whether Android clears the selected default assistant and document
   the OEM behavior.

### “Hey Nuva” and system assistant

1. Select NUVA under **Default apps → Digital assistant app**.
2. Invoke the configured assistant gesture/power shortcut; NUVA should open and start one listening
   session.
3. Enable visible wake mode and confirm the ongoing `NUVA active` microphone notification.
4. With screen on, test `Hey Nuva`, `Hey Nova`, `Hey Niva`, `হে নুভা`, and an inline command.
5. Mention “Hey Nuva” in the middle of a sentence; it must not wake.
6. Lock the screen; custom foreground wake must pause rather than claim privileged DSP behavior.
7. Kill the speech provider and use **Restart listener**; status must recover or show a clear error.
8. Disable overlay permission; verify there is no hidden UI/action.
9. Disable microphone permission while active; the service must stop and expose an error.
10. Reboot: NUVA must not silently start a boot-time microphone session.

### Existing high-risk regressions

1. Calls/messages/notification replies/file mutations/Home Assistant/Calendar provider still block on
   confirmation.
2. Financial transaction commands remain refused.
3. OTP/PIN/password/CVV content is neither read nor typed.
4. Calendar agenda reads remain bounded and no `WRITE_CALENDAR` permission appears.
5. Home Assistant rejects HTTP, arbitrary services and high-consequence device domains.
6. Picker-based file/photo/PDF flows never access an unselected item.

### Provider/OEM tests

- Google and Samsung speech providers;
- at least one Pixel, Samsung and Xiaomi/Redmi device if available;
- Calendar apps from Google and one OEM;
- one real HTTPS Home Assistant server with ambiguous and exact entity names;
- airplane mode, slow network, background battery restriction and notification-disabled states.

## Release gate

A release candidate can be marked device-verified only after:

- unit tests, lint and `assembleDebug` pass;
- APK SHA-256 is recorded;
- at least one Android 13–16 physical device completes the assistant/wake matrix;
- no confirmation, LOCAL_ONLY or credential/financial boundary regresses;
- known OEM failures are documented rather than represented as working.
