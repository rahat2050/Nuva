# NUVA v1.x Final Audit — capability matrix & architecture

Audit date: 2026-08-26 · covers v1.1 → v1.4 (this PR #15). Status labels:

* **SUPPORTED** — implemented, exercised by unit/mirror tests
* **ANDROID-LIMITED** — works only as far as Android officially permits (settings screens instead of direct toggles, verified-only automation, etc.)
* **UNSUPPORTED** — deliberately not implemented, honestly reported in the UI
* **BLOCKED** — refused by policy (financial transactions / credential handling)

## Natural-language command architecture

```
"Hey Nuva" (wake, visible session)
   ↓ full utterance (voice or typed)
PREPARE      normalize → wake-strip → Bangla numerals → hyphen suffixes ("Rohim-ke")
SECURITY     financial LEVEL-3 + credential scan → refuse without parsing
LOCAL PARSE  rule table (bn/banglish/en) → CommandDecision
COMPOUND     conservative connector split (" ar / ebong / and / tarpor / আর / এবং / তারপর")
             → validated action plan (message tails never cut)
AI (Groq)    only when the local parser does not understand; structured action only
VALIDATE     schema + registry + parameter checks (client re-validation)
ENTITY       ContactResolver (multi-match ⇒ ask) · AppLauncher · EntityNormalizers · NuvaDateTimeParser
CONTEXT      ContextMemory pronouns/app inheritance (5-min TTL)
POLICY       security validation → financial policy → risk floor
CONFIRM      blocking dialog: target, content, app, risk (SEND/CANCEL)
EXECUTE      platform intents / verified accessibility flow
VERIFY       package + recipient verification (WhatsApp), result classification
RESPOND      Bangla-first speech + UI; history records command/step/reason
   ↓ re-arm wake listening (one wake = one command + ≤2 follow-ups)
```

Nothing about the user's words is hard-coded: contact names, apps, messages,
queries, times and URLs are extracted dynamically and resolved on-device.

## Verification levels

1. **JVM unit tests** — parser (3 scripts), compounds, context memory, entity
   normalizers, failure classifier, validator, ActionJson round-trip,
   confirmation summaries, financial policy, date/time parser.
2. **Offline mirror** (`android/tools/parser_mirror_check.py`) — 1:1 logic
   mirror, ~175 assertions, all passing.
3. **On-device checklist** (manual, needs a phone): accessibility flows,
   WhatsApp verified send, media session control, wake-word popup lifecycle,
   follow-up session, notification summary.

## Known limitations

* No local Gradle build in the dev sandbox and the CI token cannot run/modify
  workflows — run the APK workflow manually (see PR).
* COMPOSE-tier messaging sends nothing automatically by design.
* Media control depends on the player posting a media notification.
